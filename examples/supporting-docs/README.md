# Supporting documents: Contextify itself

This repository demonstrates the 0.2 workflow. Its generated [AGENTS.md](../../AGENTS.md) is the short entry point. It links to two documents for tasks that need more detail:

- [Architecture](../../docs/context/architecture.md): the skill/writer/checker relationship, evidence flow and integration boundaries.
- [Workflows](../../docs/context/workflows.md): local test commands, context updates and the release workflow.

The documents are generated by the same writer, included in the same [stamp](../../.contextify/stamp.json), and have source mappings in [evidence.json](../../.contextify/evidence.json). They are not automatically imported into every agent session.

Generation preserves human content outside managed blocks. Omitting a supporting draft on a later update retains the existing file and its checking obligations; it does not silently accept an edit inside that file's managed block. Each document has its own 120-line limit.

The skill still links existing maintained docs first. These outputs are useful here because they explain relationships across the skill, scripts and CI and collect contributor procedures that do not belong in every task's initial context. They are not a requirement for a tiny repository.

See [supporting document guidance](../../docs/supporting-docs.md) and the [current feature verification](../../evals/supporting-docs.md). Earlier Next.js and Python samples remain dated 0.1 artifacts.
